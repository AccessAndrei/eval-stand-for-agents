# gateway

Входная точка Python-раннера. [server.py](server.py) обслуживает HTTP,
[runtime.py](runtime.py) координирует стадии, [store.py](store.py) сохраняет
fingerprint, состояние, события и единственный терминальный результат.
Docker target `gateway` находится в [общем Dockerfile](../../docker/Dockerfile.services).

Все маршруты, включая `/health`, требуют `CLIENT_TOKEN`. Запуск —
`python -m services.gateway.server`; Compose публикует порт 8080 только на loopback.

| Маршрут | Назначение |
|---|---|
| `POST /v0/runs` | Проверка запроса/профиля и устойчивый приём перед provision |
| `GET /v0/runs/{run_id}` | Состояние и серверный результат |
| `GET /v0/runs/{run_id}/events` | События текущей попытки |
| `POST /v0/runs/{run_id}/cancel` | Запрос отмены; освобождение подтверждается отдельно |
| `GET /v0/runs/{run_id}/artifacts` | Ограниченная копия, манифест и доверенные доказательства |

Один активный run; иной новый run получает `busy`. Идентичный повтор возвращает
сохранённое состояние, отличное содержимое под тем же id — конфликт. Авария
не возобновляет команды. Ошибка очистки удерживает блокировку новых запусков.
Удаление серверного тома завершает историю идемпотентности, выгруженные отчёты
раннера остаются в `results/`.
