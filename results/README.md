# Результаты проверок

В Git опубликованы только сводки, на которые ссылается документация.
Для чтения итогов начните с [отчёта проекта](../docs/report.md).

Сырые журналы, копии файлов сандбоксов и остальные промежуточные артефакты
сохранены локально и не входят в Git. Поэтому внутренние пути из JSON-сводок
к таким файлам работают на машине исходного запуска. Команды в README
позволяют получить новый полный набор результатов.

Новые результаты игнорируются Git. Выбранную сводку для публикации нужно
добавлять явно: `git add -f results/<путь>`.

## Имена локальных результатов

| Имя | Содержимое |
|---|---|
| Каталог с UUID | Полный набор задач: `report.json`, события и отдельная копия файлов каждой попытки |
| `offline-suite-*` | Общий инфраструктурный набор: сводка и журналы шагов; сводка ссылается на отдельные native-результаты |
| `native-*`, `native-collector-*`, `native-shutdown-*` | Проверки реального маршрута, сборщика, отмены, сбоев, восстановления и очистки |
| `live-check-*`, `luna-compat-*` | Короткие live-проверки подключения и инструментов; часть ранних попыток неуспешна |
| `source-build-*` | Компиляция Codex, журналы, хеши, измерения ресурсов и метаданные сборки |
| `validation-*` | Машиночитаемые результаты Python-тестов |
| `preflight-*` | Снимок параметров среды на момент проверки |

Время в именах каталогов указано в UTC. В `summary.json` обычно есть `passed`,
в полном наборе — `success`; причины ошибок и ссылки на доказательства находятся
внутри отчёта. Сохранённые неуспешные попытки показывают исход до исправления.

Сводки не являются исходным кодом. Исторические пути сохранены, поскольку
они записаны в сводках, отчётах и конфигурации source-build. Новые запуски
создают отдельные каталоги. Файлы с именем `auth.json` внутри `live-check-*`
содержат статусы проверки; прежние credentials сохраняются в приватном
`.auth/` вне этой папки. Текущий API-runtime их не читает; API-ключ поступает
только в окружение llm-proxy. Старые результаты не подтверждают новый API-live-маршрут.
