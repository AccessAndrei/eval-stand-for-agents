## Сборка и ресурсы

Первоначальная запись [preflight](../results/preflight-2026-11-06/environment.json) сделана до изменения настроек и решения пользователя. Она историческая: старое требование жёсткой квоты проекта 10 ГБ отменено. Используется обычный Docker Desktop с выделенными 32 ГБ диска; ведётся фактический учёт, чужие ресурсы не удаляются. Потолки CPU/RAM остаются: одна vCPU, один CPU worker, до 8 000 000 000 байт RAM.

[Первая попытка](../results/source-build-20261106T162643Z/report.json) прервана при отмене чата до компиляции. [Вторая попытка](../results/source-build-20261106T163231Z/report.json) использовала её учтённый кэш и общий исходный deadline. Rust 1.95.0, профиль upstream `dev-small`, Cargo `--locked --jobs 1`, BuildKit max-parallelism=1, лимит builder 7 000 000 000 байт и запрет дополнительного swap. Нормализация Cargo.lock допускается только для версий workspace при неизменности внешних зависимостей; patch и хеши входят в образ сборки.

Компиляция второй попытки завершилась за 10 минут 49 секунд. Пиковый расход builder — 6 999 998 464 байт, без OOM. Проверка с явным `--platform=linux/arm64` подтвердила `codex-cli 0.159.3`, `app-server` и `exec-server`. Исходный сбой проверяющей команды сохранён: в окружении пользователя был `DOCKER_DEFAULT_PLATFORM=linux/amd64`. Последующая успешная [проверка](../results/source-build-20261106T163231Z/verification.json) и [runtime provenance](../results/source-build-20261106T163231Z/provenance.runtime.json) отделены от исходного отчёта контроллера. Бинарник выгружен в игнорируемый Git каталог `build/codex-artifact`; [хеш экспорта](../results/source-build-20261106T163231Z/artifact-export.json) совпадает с метаданными сборки.

Нормализованы версии 159 локальных workspace-пакетов; внешние зависимости не обновлены. Собственный BuildKit-кэш после сохранения доказательств очищен, чужой кэш не удалялся. На момент завершения очистки внутри Docker было свободно 8,68 ГБ. Это наблюдение, а не дополнительный обещанный объём. Все образы собственных сервисов затем собраны с той же закреплённой source-build и явным ARM64; фактический маршрут проверяется отдельно.

## Статус итерации

Текущее уточнение 2026-11-14: API-ключ получает только proxy, endpoint и model id задаёт профиль, протокол подключается адаптером. Удалены прежние OAuth/device-login/refresh-процессы и четыре неиспользуемых элемента без изменения внешнего контракта. Проверка 2026-11-14 после фиксации изменений: `.venv/bin/python -m pytest -q --tb=short` — **263 passed**, 8,38 с; Ruff и проверка форматирования 115 файлов, `git diff --check` и строгая валидация OpenSpec прошли. Независимые Python- и security-ревью одобрили изменение без подтверждённых замечаний. Проверка конкретного внешнего API и новый live-набор B1.1–B5.1 пока не выполнены: оператор ещё не задал endpoint, model id и API-ключ. Старые Luna/OAuth-результаты не закрывают этот критерий.

Исторический статус первоначального объёма: согласованный сокращённый объём итерации был реализован. Source-build, стабильный ограниченный сбор, единый offline-набор, нативный refresh и live-набор B1.1–B5.1 подтверждены. Итоговые настроенные проверки и независимое ревью завершены. Проверки остановки и освобождения одноразовых сред прошли; исходные результаты успешных и отрицательных запусков сохранены.

Исторический профиль Luna использовал `observed_usage`: целевые 30 000,
остановка между запросами, допустимое превышение последним запросом и
`max_output_tokens=2048` на запрос. Подписочный счётчик входа вернул
[404](../results/luna-compat-20261106T191620Z-059d93/report.json);
отдельный [запрос с выходным пределом 16](../results/luna-compat-20261106T193257Z-7b610c/report.json)
завершился по этому пределу. Полный агентный маршрут подтверждён отдельным
набором выше. Три разовых диагностических модуля и три их тестовых файла
удалены; рабочая конфигурация больше не зависит от имени отчёта эксперимента.
Текущий API-профиль сохраняет явный `observed_usage`; его совместимость с заданным оператором upstream проверяется отдельно. Учёт обоих режимов остаётся в одном `services/llm_proxy/budget.py`.

Десктоп-клиент и клиентское монтирование отложены по согласованному объёму. Сравнение пар и выводы о свойстве базиса до измерений не делаются.
