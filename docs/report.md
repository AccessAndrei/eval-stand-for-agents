## Проверки реализации

По решению владельца в Git опубликованы только сводки. Сырые журналы, копии
файлов и промежуточные артефакты сохранены локально в `results/`; внутренние
ссылки на них из JSON-сводок требуют данных исходного запуска либо нового
прогона по командам README.

Итоговый Python-набор от 2026-11-07: **336 passed**, 9,09 с. Команда:

```bash
.venv/bin/python -m pytest -q --junitxml=results/validation-2026-11-07/python-tests.xml
make check
make pre-commit
git diff --check
```

[Итоговый JUnit](../results/validation-2026-11-07/python-tests.xml). Ruff, настроенные pre-commit hooks и `git diff --check` прошли. Предыдущая [проверка 327 тестов](../results/validation-2026-11-06/python-tests.xml) сохранена. Python-тесты используют loopback и вымышленные credentials; фактическая Docker-интеграция и live-прогоны имеют отдельные доказательства ниже.

Единая команда после подготовки образов и остановки стека — `make test-offline`.
Она проверяет source-build и один CPU Docker engine, выполняет Python/HTTP,
нативные сценарии и проверки сборщика, затем обе формы остановки. Сборок,
скачиваний образов и обращений к Luna внутри набора нет. Итог сохраняется в
новом `results/offline-suite-*/summary.json`. Команды подготовки и отдельный
live-запуск приведены в [README](../README.md).

Полный [offline-набор](../results/offline-suite-20261106T212147Z-ec76a0/summary.json) прошёл: **48 шагов**, все **20 запланированных нативных сценариев**, без пропусков. Успешны все пять проверок сборщика (`writer`, `interference`, `link-swap`, `symlink`, `size-limit`), а также остановка через `make down` и прямой `docker compose down -v`. Набор не выполнял live-запросов, сборок или скачиваний образов. Добавленный `resource_postcheck` успешен; runtime и builder остановлены.

Предыдущий [offline-запуск](../results/offline-suite-20261106T205312Z-ea34bd/summary.json) сохранён. Ограниченный таймаут оказался корректным исходом защиты сборщика; исправлено ожидание теста, приведшее к остановке того набора.

Проверены контракты, отказ при неверных версиях/профилях/путях, независимые исходы, повтор принятия без нового резерва, потеря ответа provision без replay, ошибки копирования и очистки, резерв финализации, ограничение HTTP по общему времени, пять чекеров и раннер. Для B5 проверены подмена/отсутствие доказательства, чужая попытка, shell-обёртки и сохранение отчёта при сочетании ошибок. Отдельный процессный тест проверяет завершение relay в другом PGID после смерти родителя. ## Сборка и ресурсы

Первоначальная запись [preflight](../results/preflight-2026-11-06/environment.json) сделана до изменения настроек и решения пользователя. Она историческая: старое требование жёсткой квоты проекта 10 ГБ отменено. Используется обычный Docker Desktop с выделенными 32 ГБ диска; ведётся фактический учёт, чужие ресурсы не удаляются. Потолки CPU/RAM остаются: одна vCPU, один CPU worker, до 8 000 000 000 байт RAM.

[Первая попытка](../results/source-build-20261106T162643Z/report.json) прервана при отмене чата до компиляции. [Вторая попытка](../results/source-build-20261106T163231Z/report.json) использовала её учтённый кэш и общий исходный deadline. Rust 1.95.0, профиль upstream `dev-small`, Cargo `--locked --jobs 1`, BuildKit max-parallelism=1, лимит builder 7 000 000 000 байт и запрет дополнительного swap. Нормализация Cargo.lock допускается только для версий workspace при неизменности внешних зависимостей; patch и хеши входят в образ сборки.

Компиляция второй попытки завершилась за 10 минут 49 секунд. Пиковый расход builder — 6 999 998 464 байт, без OOM. Проверка с явным `--platform=linux/arm64` подтвердила `codex-cli 0.159.3`, `app-server` и `exec-server`. Исходный сбой проверяющей команды сохранён: в окружении пользователя был `DOCKER_DEFAULT_PLATFORM=linux/amd64`. Последующая успешная [проверка](../results/source-build-20261106T163231Z/verification.json) и [runtime provenance](../results/source-build-20261106T163231Z/provenance.runtime.json) отделены от исходного отчёта контроллера. Бинарник выгружен в игнорируемый Git каталог `build/codex-artifact`; [хеш экспорта](../results/source-build-20261106T163231Z/artifact-export.json) совпадает с метаданными сборки.

Нормализованы версии 159 локальных workspace-пакетов; внешние зависимости не обновлены. Собственный BuildKit-кэш после сохранения доказательств очищен, чужой кэш не удалялся. На момент завершения очистки внутри Docker было свободно 8,68 ГБ. Это наблюдение, а не дополнительный обещанный объём. Все образы собственных сервисов затем собраны с той же закреплённой source-build и явным ARM64; фактический маршрут проверяется отдельно.

## Статус итерации

Согласованный объём итерации реализован: **33/33 задачи**. Source-build, стабильный ограниченный сбор, единый offline-набор, нативный refresh и live-набор B1.1–B5.1 подтверждены. Итоговые настроенные проверки и независимое ревью завершены. Проверки остановки и освобождения одноразовых сред прошли; исходные результаты успешных и отрицательных запусков сохранены.

По решению пользователя Luna использует `observed_usage`: целевые 30 000,
остановка между запросами, допустимое превышение последним запросом и
`max_output_tokens=2048` на запрос. Подписочный счётчик входа вернул
[404](../results/luna-compat-20261106T191620Z-059d93/report.json);
отдельный [запрос с выходным пределом 16](../results/luna-compat-20261106T193257Z-7b610c/report.json)
завершился по этому пределу. Полный агентный маршрут подтверждён отдельным
набором выше. Три разовых диагностических модуля и три их тестовых файла
удалены; рабочая конфигурация больше не зависит от имени отчёта эксперимента.
Учёт обоих режимов остаётся в одном `services/llm_proxy/budget.py`.

Десктоп-клиент и клиентское монтирование отложены по согласованному объёму. Сравнение пар и выводы о свойстве базиса до измерений не делаются.
