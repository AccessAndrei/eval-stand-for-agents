# Свои БАФ

## Свои задачи для курсовых БАФ (по одной минимум на каждую)

Для каждой Б1–Б8 требуется минимум одна собственная задача с другой фикстурой
и подвохом. Для неё нужно описать отличие от курсовой и обосновать, почему
она атомарна и проверяет функцию агента. Эти задачи пока не разработаны;
текущие B1.1–B5.1 относятся к курсовому набору.

## Своя БАФ

Пока не выбрана. Нужна новая атомарная функция агента с тремя задачами:
простой, средней и с подвохом. При добавлении нужно объяснить отличие
от восьми курсовых функций и от инфраструктурных проверок.

## Своя составная задача

Пока не разработана. Требуются формулировка, явное разложение на БАФ
и обоснование последовательности.

## Текущий курсовой набор и правила оценки

Первый набор задан явно в [checkpoint1.yaml](../baf/checkpoint1.yaml): B1.1–B5.1, по одной попытке последовательно. Полный [catalog.yaml](../baf/catalog.yaml) не расширяет этот набор автоматически.

| Задача | Действие | Проверка |
|---|---|---|
| B1.1 | Прочитать порт из YAML | Значение answer.txt; pass=false остаётся отказом даже при exit code 0 |
| B2.1 | Найти определение parse_date | Точный относительный путь |
| B3.1 | Создать config.json по спецификации | Закреплённая JSON Schema, обязательные поля и типы |
| B4.1 | Исправить версию только в Install | Точное содержимое README и отсутствие посторонних правок |
| B5.1 | Запустить исходный скрипт медианы | Ответ, неизменные входы и связанное с попыткой доказательство нативного вызова |

Каждая задача проверяет одну функцию. Это первые простые задачи курсового базиса, а не выполнение требования о собственных дополнительных БАФ или составной задаче; они остаются за пределами этой итерации.

В рабочую среду передаются только prompt и fixture. Чекеры исполняются доверенным Python вне сандбокса на полной стабильной копии. Файлы доказательства не читаются из ответа агента. Для B5.1 обязательны run/thread/turn/item id, начало и завершение commandExecution, точный разрешённый вызов Python с `-I -S`, cwd=/work, exit code 0 и манифест защищённых входов. `echo stats.py`, угаданная медиана, чужой вызов или подмена скрипта не засчитываются. Реальная защита входов и доверенность сборщика должны подтверждаться Docker-тестами.

При неполной копии — `not_run_collection_failed`; при потерянном обязательном доказательстве — `not_run_evidence_incomplete`. Это технические пропуски, а не неверные ответы модели. Усечение stdout не заменяет потерю структурированного доказательства.

[Раннер](../baf/runner/batch.py) сохраняет отчёт по всем пяти задачам, включая незапущенные. Неверный ответ и исчерпание токенов допускают следующую задачу только после успешной очистки. Ошибка очистки, недостаток места или неработоспособная инфраструктура прекращают новые запуски. Новая попытка требует нового id; автоматического повторения до успеха нет.

`make test-checkpoint1` проверяет эту логику без live-модели. `make checkpoint1 PROFILE=api` предназначен для готового gateway. Успешные синтетические ответы тестов не являются результатом измерения внешней модели.

## Формат отчёта текущего раннера

`results/<batch-id>/report.json` соответствует определению
[`report` в схеме v0](../contracts/v0.schema.json#/$defs/report).
Он содержит версию, профиль, время начала и завершения, ровно пять записей
`tasks`, счётчики `evaluated`, `wrong_answers`, `technical_skips`, общий
`success` и статус курсового допуска модели.

Каждая запись содержит `task_id`, `run_id`, серверный `result`,
`checker_status`, причины отказа или пропуска, пути к событиям и файлам,
а при ошибках — `errors`. В `result` раздельно учитываются исполнение,
сбор и очистка, время, токены и доказательства. Схема полного будущего
БАФ-бенчмарка пока не реализована.
