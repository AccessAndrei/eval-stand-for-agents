# БАФ — базисные агентские функции

Атомарные функции пары «харнес + LLM»: чтение, поиск, создание, редактирование, использование инструмента, генерация кода, рассуждение, синтез. Инфраструктура (сессии, сеть, сбои, синхронизация, изоляция) сюда не входит — она в `tests/infra/`.

Рабочий набор текущей итерации — [`checkpoint1.yaml`](checkpoint1.yaml):
B1.1–B5.1. В папках пяти задач находятся `task.yaml`, `fixture/` и `check.py`;
`runner/` запускает их последовательно. Команда — `make checkpoint1 PROFILE=api`.

[`catalog.yaml`](catalog.yaml) описывает будущий полный каталог БАФ.
Наличие записи в нём не означает готовую fixture или работающий полный бенчмарк.
Курсовой набор содержит восемь БАФ по три задачи и три составные задачи.
Собственные дополнения, их обоснования и правила оценки текущего набора:
[docs/baf.md](../docs/baf.md).

## Формат задачи

```
baf/<БАФ>/<задача>/
├── task.yaml    # id, baf, level, messages, timeout_s, answer_file, fixture_files
├── fixture/     # исходное содержимое workdir — копируется в чистую папку перед запуском
└── check.py     # программный чекер: получает путь к итоговой папке, печатает JSON {"pass": bool, "reason": str}
```

Правила:

- чекер смотрит на **итоговое состояние** (файлы, их содержимое, для Б6 — скрытые тесты), а не на текст ответа модели;
- одна задача — одна функция, укладывается в минуты;
- каждая задача стартует с чистой копией фикстуры;
- скрытые тесты и эталоны не лежат в `fixture/` — агент их не видит.

## Будущие режимы полного каталога

| Режим | Состав | Повторы | Где |
|---|---|---|---|
| smoke-БАФ | `level: simple`, по одной на БАФ | 1 | CI: «отработало, файл создан, ничего не сломалось» |
| полный | все основные + дополнительные + составные задачи | 3 | тесты на качество, сравнение пар |

Эти режимы ещё не реализованы. Текущий раннер сохраняет
`results/<batch-id>/report.json` с результатами B1.1–B5.1, событиями и файлами
попыток; формат описан в [docs/baf.md](../docs/baf.md).
