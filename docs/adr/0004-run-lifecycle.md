# ADR-0004: одна попытка и восстановление без повторного исполнения

- Статус: accepted
- Дата: 2026-11-06

## Контекст

Потеря HTTP-ответа не означает, что среда не создана или команда не выполнена. Повтор команды может изменить результат; неполная копия не позволяет судить о качестве модели.

## Решение

Один активный run, одна среда и один разговор. До побочных эффектов сохраняются запрос, fingerprint и резерв финализации. Идентичный повтор возвращает прежний run, другое содержимое даёт конфликт, новый run при занятости — busy.

После аварии сохраняется уже записанный терминальный результат либо фиксируется interrupted после сверки собственных ресурсов. Команды не воспроизводятся. Раздельно сохраняются execution/collection/cleanup; раннер добавляет checker и ошибки переноса файлов. Ошибка поздней стадии не заменяет первопричину. Слот остаётся занят до освобождения харнесса/relay, сбора, очистки и сохранения результата.

До начала набора резервируется отчёт по всем пяти task id. Прикладные резервы расходуются на фактические записи, финальный резерв отделён. История и результаты не удаляются автоматически ради места. Явное удаление истории прекращает гарантию идемпотентности для удалённых id.

## Альтернативы

| Вариант | Преимущество | Причина отказа |
|---|---|---|
| Автоматически повторять POST/команды | Может скрыть краткий сбой | Повторяет уже выполненные побочные эффекты |
| Только exit code агента | Простой итог | Не доказывает правильность файла и успешную очистку |
| Очередь и параллельные сессии | Выше пропускная способность | Не входят в первую итерацию |

## Последствия

Очистка с неопределённым исходом блокирует новые задачи. Потерянный usage требует удержать резерв и отметить неизвестность, а не писать нулевой расход. Серверный результат и отчёт раннера различаются: сервер не выполняет доверенный чекер.
