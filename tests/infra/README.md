# Инфраструктурные проверки

Здесь находятся проверки с настоящими Codex и Docker-сандбоксами.
После подготовки образов и остановки стека запустите из корня репозитория:

```bash
make test-infra
```

| Файл | Назначение |
|---|---|
| `offline_suite.py` | Общий последовательный набор: Python-тесты, native-сценарии, сборщик и очистка |
| `native_probe.py` | Команды, patch, переключение профиля, отмена, бюджет, сбои и восстановление |
| `collector_probe.py` | Фоновая запись, вмешательство агента, подмена ссылок и предел копирования |
| `native_shutdown.py` | Проверка `make down` и прямого `compose down -v` |
| `mock-scripts/` | Фиктивные Responses-ответы для воспроизводимых вызовов инструментов |

Набор не обращается к внешней модели, не собирает и не скачивает образы.
Подготовка описана в [инструкции запуска](../../docs/harness.md#инфраструктурные-проверки), доказательства — в
[отчёте](../../docs/report.md). Ошибки сохраняются; динамические среды очищаются.
Компонентные проверки без Docker находятся в `tests/test_*.py`.

## Требуемые группы проверок

Шаблон курса предусматривает следующие группы с mock LLM, без внешней сети.
Наличие группы в таблице не означает её полного прохождения; подтверждённые
сценарии перечислены в [отчёте](../../docs/report.md).

| Группа | Требуемое покрытие |
|---|---|
| Контракты | Схемы обоих протоколов и граничные случаи; клиентский и полный нативный контракт пока не описаны |
| Инварианты | Ровно один result, идемпотентность, отмена дерева процессов, таймауты операций, отсутствие секретов в сандбоксе |
| Лимиты и очистка | CPU, RAM, PIDs, диск, время; отсутствие процессов и временных ресурсов после сессии |
| Изоляция | Выход за workdir, внешние симлинки, canary-секрет, fork bomb, заполнение диска, запись в ro; текущие проверки сборщика не заменяют весь набор |
| Сеть | Разрешённое доступно, запрещённое заблокировано, обход невозможен |
| Сбои | Обрывы монтирования и клиента, падение харнеса посреди команды, политика ретраев; клиент и монтирование пока отсутствуют |
| Сессии | Продолжение в новой сессии и изоляция параллельных сессий; сейчас разрешён один активный run |
| Синхронизация | Правки видны в обе стороны, конфликт одновременной правки обрабатывается по ADR; пока не реализовано |

Включение UI, инфраструктуры и smoke-БАФ в единый CI остаётся требованием
задания A; сейчас `make test-ci` завершается ошибкой из-за отсутствующих частей.
