# БАФ — базисные агентские функции

БАФ проверяют чтение, поиск, создание и редактирование файлов, использование
инструментов, генерацию кода, рассуждение и синтез источников. [Инфраструктурные тесты](../tests/infra/README.md)

[`catalog.yaml`](catalog.yaml) описывает 24 атомарные задачи и три составные.
[`control.yaml`](control.yaml) объединяет готовые задачи B1.1–B5.1,
а [`smoke.yaml`](smoke.yaml) включает по одной простой задаче Б1–Б8. Пример
структуры - [B1.1](B1-read/B1.1-service-port). [Собственные БАФ](../docs/baf.md)

## Формат задачи

```
baf/<БАФ>/<задача>/
├── task.yaml    # id, baf, level, messages, timeout_s, answer_file, fixture_files
├── fixture/     # исходное содержимое workdir — копируется в чистую папку перед запуском
└── check.py     # программный чекер: получает путь к итоговой папке, печатает JSON {"pass": bool, "reason": str}
```

Правила:

- Чекер проверяет итоговые файлы и, для B5.1, доказательство вызова инструмента.
- Атомарная задача проверяет одну функцию и укладывается в минуты.
- Каждая задача стартует с чистой копией фикстуры в отдельной локальной
  папке. Раннер сохраняет двоичные байты. Лимит - 256 файлов и 1 000 000 байт
  в исходной фикстуре.
- Раннер исполняет доверенные чекеры вне сандбокса. Загружайте только датасеты,
  чекерам которых доверяете. Фикстура содержит только исходные данные агента.

Для B5.1 проверяются числовой ответ, неизменность входных файлов и
доказательство точного вызова исходного скрипта. Доказательство связывает
`run_id`, `thread_id`, `turn_id` и `item_id` с началом и завершением
`commandExecution`, вызовом Python с `-I -S` из `/work`, кодом возврата 0
и манифестом защищённых входов. [Чекер B5.1](B5-tool/B5.1-median/check.py)

## Режимы прогона

| Режим | Состав | Повторы | Где |
|---|---|---|---|
| smoke-БАФ | `level: simple`, по одной на БАФ | 1 | CI: «отработало, файл создан, ничего не сломалось» |
| полный | все основные + дополнительные + составные задачи | 3 | тесты на качество, сравнение пар |

Раннер выполняет по одной попытке на задачу из указанного датасета. Манифест YAML
содержит `version: 0` и непустой список `tasks` с уникальными `id`.
Каталоги `directory` задаются относительно манифеста. Раннер проверяет весь
набор до начала выполнения.

На готовом стеке запустите датасет с настроенным профилем.

```bash
make baf DATASET=baf/control.yaml PROFILE=api
```

Для прямого запуска передайте `CLIENT_TOKEN` запущенного gateway в окружении.
По умолчанию используется `http://127.0.0.1:8080`. Другой адрес задаётся
в `GATEWAY_URL`.

```bash
.venv/bin/python -m baf.runner --dataset baf/control.yaml --profile api
```

Для офлайн-прогона запустите mock-стек с
`MOCK_SCRIPT_PATH=/mock-scripts/baf-smoke/playlist.json`. Плейлист выбирает
запись по тексту задачи. На готовом стеке запустите smoke.

```bash
make baf-smoke
```

Для контрольного mock-прогона укажите при запуске стека
`MOCK_SCRIPT_PATH=/mock-scripts/baf-smoke/control-playlist.json`.

```bash
make baf DATASET=baf/control.yaml PROFILE=mock
```

В контрольном режиме раннер сохраняет `results/<batch-id>/report.json` со строкой для каждой
задачи датасета по порядку, включая незапущенные. Отчёт содержит профиль,
исходы исполнения, сбора, проверки и очистки, время, токены и ссылки на
артефакты. Счётчики `evaluated`, `wrong_answers` и `technical_skips`
рассчитываются по строкам отчёта. `success` подтверждает успешное исполнение,
полный сбор, пройденную проверку и успешную очистку каждой попытки.
[Схема отчёта v1](../contracts/mounted_report.schema.json)

Неподтверждённое состояние рабочей папки даёт `not_run_collection_failed`, потеря обязательного
доказательства - `not_run_evidence_incomplete`. После неверного ответа или
исчерпания токенов раннер переходит к следующей задаче при исправной
инфраструктуре и успешной очистке. При ошибке инфраструктуры, очистки
или нехватке места оставшиеся задачи отмечаются `not_run` с причиной.
