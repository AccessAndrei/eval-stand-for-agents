# ADR-0005: API-ключ и адаптеры протокола провайдера

- Статус: accepted
- Дата: 2026-11-14

## Контекст

Подписочная ChatGPT-авторизация требовала device-login, refresh, отдельного владельца credentials и восстановления ротации. Пользователь выбрал прямой API-ключ и возможность подключить будущий model endpoint без изменения раннера или среды исполнения. Старые live-результаты относятся к прежнему способу доступа.

## Решение

Профиль задаёт endpoint, model id, протокол, параметры ожидания и имя переменной ключа. Профиль `api` разрешает `MODEL_ENDPOINT` и `MODEL_ID` из окружения proxy; ключ поступает только туда как `MODEL_API_KEY`. В снимок попадают параметры и имя переменной, значение ключа не сохраняется. API-ключ передаётся удалённому endpoint только по HTTPS; HTTP допустим для localhost и числового loopback в локальной проверке. Harness получает только токен конкретной попытки для внутреннего посредника; агентные команды и менеджер не получают upstream-ключ.

Upstream-протокол реализуется отдельным модулем из явного реестра `services/llm_proxy/providers/`. Первым поддерживается Responses; другой API требует адаптера запроса, потока и usage. Переключение совместимого endpoint выполняется профилем. Неподдерживаемый протокол и неполная конфигурация отклоняются до provision. Device-login, auth-only Codex, refresh и callback удалены. После отказа авторизации нет повторного inference, смены модели или redirect. Старый `.auth/` не читается и не удаляется миграцией.

## Альтернативы

| Вариант | Преимущество | Причина отказа |
|---|---|---|
| Сохранить OAuth вместе с API-ключами | Прежний способ доступа остаётся рабочим | Сохраняет отвергнутую пользователем сложность и два жизненных цикла авторизации |
| Передать API-ключ непосредственно Codex | Меньше proxy-кода | Расширяет число процессов с ключом и обходит единый учёт upstream |
| Считать любой endpoint совместимым после смены URL | Минимум настройки | Форматы запросов, tool calls, потоков и usage различаются |

## Последствия

Оператор задаёт endpoint, модель и ключ в приватной конфигурации; автоматическое обновление ключа не требуется. Совместимый endpoint подключается без изменений заданий и сандбокса, иной формат — через небольшой адаптер. Наличие конфигурации или mock-тестов не доказывает совместимость реального провайдера; перед live-демонстрацией нужны новый запрос и новый набор пяти задач. История прежней Luna/OAuth-реализации сохраняется отдельно. Режим `observed_usage` остаётся целевым бюджетом между запросами, не строгим суммарным потолком.
