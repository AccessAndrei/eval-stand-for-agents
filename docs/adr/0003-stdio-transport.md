# ADR-0003: stdio через аутентифицированный CONNECT

- Статус: accepted
- Дата: 2026-11-06

## Контекст

Сандбокс не имеет сети, а харнесс не получает Docker socket. Штатный exec-server поддерживает stdio. Нужен канал, не меняющий протокол инструментов.

## Решение

Доверенный Python-relay открывает внутренний CONNECT менеджера по handle, project и run id. Менеджер запускает только фиксированный `codex exec-server --listen stdio` в принадлежащем проекту контейнере. Non-TTY Docker CLI разделяет stdout и stderr. Relay передаёт stdout без примеси диагностики, с backpressure и обработкой EOF; stderr ограничен. Обрыв не вызывает replay или локальное исполнение.

## Альтернативы

| Вариант | Преимущество | Причина отказа |
|---|---|---|
| Прямой Docker exec из харнесса | Простой прототип | Требует Docker socket в харнессе |
| WebSocket exec-server | Штатный сетевой протокол | Требует отдельной доступной сети у сандбокса |
| Собственные RunCommand/WriteFile | Произвольный контракт | Дублирует штатные инструменты Codex |

## Последствия

Канал требует тестов авторизации, побайтовой передачи, независимого stderr, EOF и отказа исполнителя. Нативный Codex создаёт relay в отдельной группе процессов; очистка адаптера проверяет всю сессию app-server, а не только PGID родителя. [Relay](../../services/harness/relay.py), [tunnel](../../services/sandbox_manager/tunnel.py).
