# Контракты

| Файл | Протокол |
|---|---|
| [v0.schema.json](v0.schema.json) | запуск, состояние, события, результат, артефакты, отчёт раннера и управление средой |
| [validation.py](validation.py) | проверка схем и согласованности независимых исходов, токенов и доказательств |

Текущая версия — `v0`. Gateway принимает запуск, отдаёт статус и поток событий,
отменяет попытку и возвращает артефакты. Менеджер предоставляет provision,
lookup по run id, collect и release; байты нативного exec-server передаются через
аутентифицированный CONNECT. После обрыва команды не переисполняются.
Пользовательские сессии и переподключение десктоп-клиента отложены.

Результат отдельно фиксирует исполнение, сбор, очистку и ошибки по стадиям.
Чекер оценивает только полную независимую копию. Учёт токенов указывает режим
`strict` или `observed_usage`, фактический расход либо причину его неизвестности.
Поведение описано в [документации харнесса](../docs/harness.md).

Текущие управляющие сообщения двух направлений представлены определениями
одного файла с общими типами, без дублирования схем:

| Направление | Определения `v0.schema.json#/$defs/…` |
|---|---|
| Клиент/раннер ↔ gateway | `launch`, `status`, `event`, `result`, `cancel` |
| Управляющая часть ↔ sandbox-manager | `provision`, `lookup`, `collect`, `release`, `manager_cancel`, `connect`, `manager_status` |

Для отдельного сообщения используется соответствующий `$ref`; проверять только
корень файла без выбора определения недостаточно. Полные клиентские сессии
и протокол монтирования в текущую v0 не входят.

Полный контракт A-6.1 должен также описывать подключение, пользовательскую
сессию, сообщение и переподключение клиента. Для A-6.2 требуется схема
`exec` (RunCommand / ReadFile / WriteFile), потока событий и единственного
финального результата. Сейчас выполнение идёт по нативному протоколу
exec-server закреплённого Codex через CONNECT; `command_event` описывает
собранные доказательства вызова, но не весь этот протокол. Его полная
машиночитаемая схема здесь не опубликована, поэтому A-6 целиком не закрыт.

Модель ошибок исполнения различает `command_error`, `timeout`,
`sandbox_error` и `transport_error`. Ошибку команды харнес может обработать
внутри текущего turn; таймаут команды или turn завершает текущую попытку.
Ошибки сандбокса и транспорта завершают попытку без повторного исполнения команды.
Автоматического перезапуска попытки нет; повтор запуска с тем же run id
и содержимым получает сохранённое состояние. Политика восстановления описана
в [ADR-0004](../docs/adr/0004-run-lifecycle.md).
